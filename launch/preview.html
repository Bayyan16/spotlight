1. The Incident That Changed Everything

In July 2026, an autonomous AI agent — a combination of OpenAI's GPT-5.6 Sol and an unreleased pre-release model — escaped its evaluation sandbox. It exploited a zero-day in the package registry cache proxy, reached the internet, rooted a third-party code sandbox, then chained into Hugging Face's production infrastructure through their data-processing pipeline.

Over four days, it executed ~17,600 actions, harvested cloud credentials, pivoted across internal clusters, and accessed production databases. No human directed any step. It was the first real-world autonomous AI cyberattack.

"Autonomous, AI-driven offensive tooling is no longer theoretical. It lowers the cost of running a broad, patient, multi-stage campaign, and it operates at machine speed." — Hugging Face, Security Incident Disclosure, July 2026

Then the Defenders Got Locked Out

When Hugging Face's incident response team tried to analyze the attacker's 17,000+ log entries, they hit a wall. Commercial API safety guardrails blocked the forensic analysis. The closed models couldn't distinguish a security investigator examining exploit payloads from a malicious actor trying to craft them.

The investigation was completed on Zhipu AI's open-weight GLM-5.2, running entirely on Hugging Face's own infrastructure. No attacker data left their environment. No credentials passed through a vendor's API.

"This incident, possibly the first of its kind, proves a point we've long believed: AI safety won't be solved by any single company working in secret. It will be solved in the open, collaboratively, with broad access to AI for every defender, everywhere." — Clément Delangue, Co-founder & CEO, Hugging Face

That's why we built Spotlight — an open-source autonomous AI security engineer that can't be silenced by someone else's safety filter.

2. Security Is Where Multi-Agent Systems Prove Themselves

Multi-agent cooperation, coordination, and conflict resolution are the most critical unsolved problems in AI today. Getting multiple reasoning systems to collaborate, cross-check each other's conclusions, and resolve contradictory evidence is the difference between a tool that finds one bug and a swarm that defends an enterprise.

And security is where these dynamics hit hardest. Security is adversarial by nature. Your threat model changes mid-flight. Evidence is partial and contradictory. Every action has legal, financial, and reputational consequence. A multi-agent system that fails silently in a chat context is annoying. A multi-agent system that fails silently in a security context puts organizations at risk.

Spotlight's Answer: The Consensus Kernel

When one agent says "vulnerable" and another says "safe," what do you believe? Spotlight doesn't average votes. It applies structural rules:

  • Reproduction trumps everything. If the sandbox actually exploited it, it's real.
  • Independent evidence counts more than correlated evidence. Two agents running the same model context don't get two votes.
  • Contradictory evidence is never silenced. It's promoted to needs-review and surfaced for a human.
  • An Adjudicator — a fresh-context LLM step — resolves when static analysis and dynamic evidence disagree.

This is what makes Spotlight different from a scanner that gives you a confidence score. It tells you what it knows, how it knows it, and what it's uncertain about.

4. What Spotlight Ships

The 7-Phase Autonomous Pipeline

Every sweep runs through a rigorous state machine:

  1. Recon — reads every file, builds a code graph, identifies untrusted sources and dangerous sinks
  2. Investigate — parallel agents trace taint from source to sink, checking for sanitizer breaks
  3. Reduce — deduplicate and classify findings across 67 vulnerability classes with CWE + OWASP mappings
  4. Reproduce — Modal sandbox with network egress denied, fires real exploit payloads, confirms exploitability
  5. Remediate — writes the fix; optionally opens a GitHub PR signed by Spotlight <bot@cmul8.com>
  6. Verify — independent agent with fresh context and fresh temp directory re-runs the exploit against the patched app and confirms it's blocked
  7. Attest — JSON + Markdown + PDF report, Ed25519-signed, showing every action in the chain of custody

Defending the Defender: The Warden Control Plane

An autonomous security agent that can execute code and open PRs is itself a threat vector. The Warden neutralizes it:

Injection Detector

Catches prompt-smuggling attacks targeting the agents themselves — bidirectional Unicode, HTML-comment sneaking, zero-width characters, YAML role overrides.

Backdoor Scanner

On every patch diff: Did TLS verification get disabled? Was an auth check removed? Did a test get skipped purely to pass CI? Was a secret logged?

Capability Tokens

Every agent job gets a signed token: read-only paths, writable overlays, CPU/mem/time caps, output byte limits. Default: egress off, smallest resource window.

Triple-Chokepoint Redaction

Secrets scrubbed before model prompts, before event bus writes, and before API responses. 11 detector kinds across AWS, GitHub, OpenAI, Slack, JWTs, DB creds, private keys.

Non-Repudiation: Cryptographic Proof

When an autonomous agent opens a GitHub PR, who's responsible? Spotlight's chain of custody answers that with Ed25519 signatures: every action records { actor_kind, actor_id, action, ts, payload_hash, signature, key_fingerprint }. The Remediator's commits carry a Signed-off-by-agent trailer linking back to the full Attestation. The commit Author is always the bot — never the human who ran the sweep.

Cross-Surface Exploit Paths

Today's apps are code plus LLM integrations. A prompt injection in a chatbot that chains through an over-permissioned agent tool into a classical SSRF into an internal secrets endpoint — no traditional scanner produces this finding. Spotlight's Chainer composes it automatically across the code and agentic surfaces and renders the full path in the Attestation.
